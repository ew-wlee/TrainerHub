# 产品说明 · TrainerHub

> 面向单机玩家的修改器管理器。本文记录问题定义、功能取舍与指标设计，
> 供 review 与后续迭代使用。

## 1. 问题定义

单机玩家找修改器时，真实发生的动作是：

1. 在搜索引擎里搜「游戏名 + 修改器」；
2. 打开 2–4 个来源不同的站点，逐个比对版本，判断哪个还对应当前游戏版本；
3. 进入详情页，被网盘/广告页/多层跳转劝退；
4. 下载后手动解压、改名、丢进某个文件夹；
5. 游戏更新后重来一遍，并且**无法确定本地哪些已经过期**。

痛点不在「找不到」，而在**多源信息碎片化 + 版本状态丢失 + 操作链路重复**。

## 2. 目标用户

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 主要用户：单机玩家 | 有 3–10 款在玩/待玩的单机游戏，愿意折腾但不想折腾下载流程 | 少开标签页，少做重复动作 |
| 次要用户：修改器收集者 | 会长期保存多个版本，常在离线环境使用 | 版本可追溯、目录可读 |
| 边缘用户：自带索引的进阶用户 | 有自己的游戏列表或私有源 | 可配置的数据源 |

## 3. 用户旅程与关键决策点

```
想改游戏
  └─ 打开 TrainerHub
       ├─ 直接搜索（不知道确切名字 → 拼音/首字母也能命中）
       ├─ 扫描 Steam 已安装游戏 → 个性化推荐 → 下载所选
       └─ 点开详情
            ├─ 看清楚：版本 / 支持的游戏版本 / 修改项清单 / 文件大小
            ├─ 判断：可直下 or 需要跳转网盘（界面上明确标注）
            └─ 下载 → 自动归档 → 提示"已完成"
                  └─ 下次启动：若有新版本，库里出现更新角标
```

关键决策点只有两个：**这条记录能不能直接下**、**我本地这个版本是不是最新的**。
界面把这两件事放在第一优先级。发现首屏仅保留游戏名、来源和必要操作状态；匹配置信度、推荐依据、大小及隐私说明放到详情或设置，不重复提醒用户。空搜索词显示推荐计划，输入后切换为本地与联网搜索，清空则恢复计划。生成计划不触发下载，外链不算已安装。

## 5. 关键取舍（以及为什么）

**1) 为什么不做「社区上传」？**
它需要三样东西：可写的服务端、文件存储与带宽、人工安全审核流程。三者都不是
一个桌面客户端能承担的，且一旦做不好就是**分发未审核可执行文件**的责任问题。
替代方案是「本地导入 + 自定义 JSON 源」，把扩展能力交给用户自己托管。

**2) 为什么小幸只做索引和跳转？**
它的分发走百度网盘/MediaFire，没有稳定直链。硬做解析既脆弱又容易触发风控。
产品上的处理是**把不确定性显式化**：列表和详情都标注「跳转下载」，点击后用浏览器
打开原页——用户预期正确，就不会觉得是 bug。

**3) 为什么下载完成后不自动运行 exe？**
下载物来自第三方站点，自动执行等于把用户暴露在不可控风险下。程序只做归档，
运行必须由用户在库里主动点击并二次确认。这条边界同时解释了为什么"打开文件夹"
比"一键启动"更常出现在主按钮上。

**4) 为什么明确不做反作弊绕过？**
面向在线游戏的绕过属于明确的服务条款违规，且会把工具从"单机便利"变成"作弊工具"。
产品只做风险提示（"仅限单人离线"），不做规避手段。

**5) 为什么在 AI 能力上选择不接入 LLM？**
这一版的目标是把**核心链路的确定性**做扎实（解析、下载、归档、版本比对）。
把一个不确定的生成层叠在未验证的管道上，只会掩盖问题。AI 方向的设想写在
roadmap 里，作为验证过基础体验之后的下一步。

## 6. 指标设计

真实数据无法获取，因此指标按"可观测、可埋点"的方式定义：

| 层级 | 指标 | 定义 | 目标 |
| --- | --- | --- | --- |
| 北极星 | 周有效归档数 | 一周内成功归档且被打开过目录的次数 | 反映"真的用上了" |
| 激活 | 首次同步完成率 | 首启向导 → 同步完成的比例 | ≥ 85% |
| 效率 | 从搜索到开始下载的耗时 | 中位数 | < 25 s |
| 覆盖 | 搜索命中率 | 有结果 / 有搜索行为 | ≥ 90% |
| 质量 | 下载成功率 | 完成 / 发起 | ≥ 95%（可直下源） |
| 留存 | 7 日内二次打开 | 安装后 7 天内再次启动 | ≥ 40% |
| 健康 | 解析失败率 | 适配器异常 / 同步次数 | < 2% |

## 7. 已知限制

- 风灵月影的列表接口不返回版本号，版本只在详情页的附件名里，因此**首页条目在
  打开详情前不显示版本**。这是数据源限制，不是遗漏。
- 小幸的「支持版本」是一句自然语言（"所有PC平台版本游戏"），无法结构化成可比较的
  版本区间，只能原样展示。
- 站点改版会导致适配器失效；程序会降级为"打开原站页面"，不会崩溃。
- 仅打包 Windows 版本；macOS/Linux 走源码运行。
